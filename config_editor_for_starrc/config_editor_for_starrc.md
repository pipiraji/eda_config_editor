# 📄 StarRC 환경 파일 자동화 스크립트 개발 계획서

## 1. 시스템 개요

본 스크립트는 Synopsys StarRC 추출(Extraction) 설정 파일의 구조(`커맨드: 값`)를 인식하고, 사용자의 명령어(Action)에 따라 설정값을 안전하게 조작(수정, 추가, 삭제, 주석 관리)하는 자동화 툴입니다.

### 1.1 용어 및 파일 구조 정의

- **Action (명령어):** 스크립트 실행 동작 (`uncomment`, `update`, `set`, `delete`)
- **Command (커맨드):** 설정 항목의 이름 (예: `NETLIST_FILE`, `EXTRACT_RES`)
- **Value (값):** 커맨드에 할당되는 실제 데이터 (예: `output.spf`, `YES`)
- **구조 특징:** 옵션(Option) 계층이 없는 **1차원 평면(Flat) 구조** (형식: `COMMAND: VALUE`)
- **주석(Comment):** 라인 맨 앞의 `*` 기호
    > **CLI 실행 형태 (프로젝트 루트 기준):**
    > `python config_editor_for_starrc/config_editor_for_starrc.py [파일명] [명령어] --command [커맨드명] --value [값]`
    > _(예: `python config_editor_for_starrc/config_editor_for_starrc.py config_editor_for_starrc/starrc.cmd set --command NETLIST_FILE --value "output.spf"`)_

## 2. 핵심 설계 원칙 및 프리프로세싱 (Preprocessing)

QRC와 동일하게 파일 직접 수정을 지양하고, 메모리 기반의 상태 관리를 통해 안정성을 확보합니다.

1. **평면화 캐싱 (Flat Key-Value Mapping):**
   파일을 한 줄씩 읽어 `커맨드 -> 값` 형태의 1차원 리스트 또는 딕셔너리로 메모리에 로드합니다. 각 라인의 주석(`*`) 여부와 원본 인덱스(줄 번호)를 상태값으로 기억합니다.
2. **명령어 체이닝 (Action Chaining):**
   `set` -> `update` -> `uncomment` 순으로 필요한 하위 명령어를 자동 호출하여 로직의 중복을 제거합니다.
3. **상태 동기화 (State Sync):**
   메모리 상에서 데이터가 변동(예: `uncomment`로 상태 활성화)되면, 이를 즉시 반영한 후 다음 단계의 검색/수정 작업을 진행합니다.

## 3. 명령어(Action)별 상세 명세

계층(옵션)이 없으므로 로직이 더 직관적이며, 대상은 항상 **"커맨드"** 기준이 됩니다.

### ① uncomment (주석 해제)

- **매칭 대상:** `--command`와 `--value` 모두 정규표현식(Regex)을 지원하며, 입력된 모든 조건의 **AND 조건**으로 대상을 찾습니다.
- **동작 로직:**

1. 정규식 조건에 부합하는 모든 대상 라인을 찾습니다.
2. 해당 라인이 주석 처리(`*`)되어 있다면, 맨 앞의 `*` 기호를 제거하여 활성화합니다.

### ② update (수정 전용)

- **선행 작업:** 내부적으로 `uncomment` 로직을 먼저 실행합니다.
- **매칭 대상:** `--command`에 정규표현식을 지원합니다.
- **동작 로직:**

1. 활성화된 라인 중 조건에 맞는 커맨드를 찾아 새로운 값으로 변경합니다.
2. 콜론(`:`) 또는 공백 등 기존의 구분자(Separator) 포맷을 그대로 유지하여 값을 덮어씁니다.

- **보완점 (값 literal 처리):** 업데이트할 `--value` 인자에는 정규표현식 동작을 허용하지 않으며, 입력된 문자열 그대로를 사용합니다.

### ③ set (설정 또는 추가)

- **선행 작업:** 내부적으로 `update` 로직을 먼저 실행합니다.
- **동작 로직:**

1. `update`가 성공하여 값이 변경되었다면 종료합니다.
2. 매칭되는 커맨드가 없어 `update`가 무시되었다면, 파일의 **가장 마지막 줄**에 `커맨드: 값` 포맷으로 새로운 라인을 추가합니다.

- **매칭 대상 (정규식 불가):** `--command`에 정규표현식을 허용하지 않습니다. 입력된 문자열과 정확히 일치하는 대상을 찾거나 생성합니다.
- **보완점:** `--value`는 입력된 문자열 그대로(literal) 사용됩니다.

### ④ delete (삭제 - Soft Delete)

- **매칭 대상:** `--command`와 `--value` 모두 정규표현식을 지원하며, 입력된 모든 조건의 **AND 조건**으로 대상을 찾습니다.
- **동작 로직:**

1. 조건에 맞는 커맨드 라인을 찾아 맨 앞에 `*` 기호를 삽입하여 **주석 처리(비활성화)** 합니다.
2. 이미 주석 처리되어 있는 라인은 건너뜁니다.

## 4. StarRC 특화 예외 처리 및 안정성 확보 (Safety Guards)

1. **정규식 `*` vs 주석 `*` 충돌 방지 (Critical):**

- StarRC는 주석 기호로 `*`를 사용합니다. 파이썬의 `re` 모듈에서 `*`는 "0회 이상 반복"을 의미하는 메타문자입니다.
- **해결책:** 프리프로세싱 단계에서 맨 앞글자가 `*`인지 먼저 검사(Literal Check)하여 주석 여부를 판별한 후, 내부 문자열에 대해서만 정규표현식 매칭을 수행하도록 **파서(Parser)의 우선순위를 엄격히 분리**합니다.

2. **구분자(Separator) 유연성 확보:**

- `COMMAND: VALUE`, `COMMAND : VALUE`, `COMMAND VALUE` 등 사용자나 환경에 따라 콜론과 공백의 사용이 혼재할 수 있습니다.
- 정규식을 통해 구분자를 `(?:[:\s]+)` 형태로 유연하게 매칭하되, **수정(`update`) 시에는 원본의 구분자 형태를 그대로 보존**하여 덮어쓰도록 설계합니다.

3. **Dry-run (시뮬레이션) 모드 필수:**

- 파일 덮어쓰기 전, 콘솔에 변경/추가/주석 처리될 라인의 `[Before] -> [After]`를 미리 출력하여 사용자가 검증할 수 있도록 `--dry-run` 인자를 지원합니다. (자동 백업 기능은 포함하지 않습니다.)
